# 問題の取り込み・追加フロー

すべての問題は**下書き(draft)**から始まり、人が出典を確認して**確認済み(confirmed)**にして初めて出題対象になる。AIが作った内容を人の確認なしに確認済みにしない。

## 1. 入口を選ぶ

| 入口 | 使う場面 |
| --- | --- |
| PDF取り込み | IPA公開の過去問PDFがある(`ANTHROPIC_API_KEY` が必要) |
| 管理画面「AIで下書き生成」 | オリジナル問題で在庫を増やしたい(`ANTHROPIC_API_KEY` を設定した環境のみ表示) |
| 管理画面「問題を追加」 | 1問ずつ手で入れる |

## 2. PDFから取り込む

1. 過去問の**利用条件を運営と確認**する(未確認なら取り込まない。企画書のリスク欄)。
2. 変換: `npx tsx scripts/pdf-to-json.ts <過去問.pdf> questions.json`
3. `questions.json` を**人の目で全件確認・修正**する。見るところ:
   - `answer` が正しいか(ア=0, イ=1, ウ=2, エ=3)
   - 選択肢がちょうど4つか、文章だけで成立しているか(図表が必要な問題は除外)
   - `source` に回次と問番号があるか(例: `令和5年度 問10`)
4. 取り込み: `DB_PATH=<本番のDBパス> npx tsx scripts/import-questions.ts questions.json`
   - 結果は `imported` / `skipped` / `errors`。同じ問題文は重複させずスキップされる。`errors` があれば該当indexを直して再実行。
   - 本番DBに入れる前に、`DB_PATH=/tmp/check.db` などの一時DBで一度試す。

## 3. AI生成の下書きを確認する

- 生成された問題は出典が空。内容を見て、**正解が一意に正しいか・事実として正しいか**を自分で確かめてから出典を入れる。
- 編集画面の「AIで解説を生成・検証」は解説案を入力欄に入れるだけで保存しない。正解に疑義の警告が出たら、問題文か正解を直すか、その問題を削除する。
- 出典はAI生成でも空欄にせず、根拠にした資料(公式の用語集・シラバスなど)を書く。

## 4. 確認済みにして出題に乗せる

1. 管理画面 `/admin/questions` で内容を確認し「確認済みにする」(出典が空だと拒否される)。
2. 特定の日に出したい問題は `/admin/queue` で日付を指定して予約する。予約がない日は、未出題の確認済みからランダムに選ばれる。
3. 一覧上部の「未出題の在庫」が少ない(既定5問以下)と運営チャンネルに警告が出る。目安として在庫は常に余裕を持たせる。

## やらないこと

- 確認なしでの確認済み化、一括の確認済み化。
- 出題済み・出題予定の問題の削除(管理画面でも拒否される)。直したいときは編集する。投稿済みの解説は自動では書き換わらないので、必要ならSlackで手動訂正する。
- トークンやAPIキーを会話やコミットに出すこと(`.env` に書く)。
